# Neo Technical Specification

This document is the canonical technical description of the current Neo
decision model and its English-only training run.

## Model

- Category: System One decision model.
- Architecture: bidirectional Transformer encoder.
- Trainable parameters: 41,391,654 (approximately 41.4 million).
- Transformer layers: 8.
- Hidden size: 512.
- Attention heads: 8.
- Intermediate size: 2048.
- Maximum context: 1,024 tokens.
- Tokenizer: `bert-base-uncased`.
- Language: English only.
- Decision heads: `choice`, `score`, and `noul`.

Neo consumes application state plus a declared question schema and returns
typed probabilities. It does not generate free-form responses.

## Decision capacity

- `choice`: up to 32 options per question.
- `score`: up to 5 ordered levels.
- `noul`: binary probability.
- Request design: up to 8 independent questions in one encoded request.
- Training tool catalog: 20 tools.
- Typical generated training case: 6 candidate options, including one target
  and distractor tools.

The 32-option head is the architectural limit. The training corpus primarily
uses six-option cases, so larger option counts require explicit evaluation
before production use.

## Training corpus

- Records: 400,000.
- Individual decisions: 1,000,000.
- Training decisions: 799,882.
- Calibration decisions: 100,138.
- Test decisions: 99,980.
- Generator: `neo-english-synthetic`.
- Language policy: English-only state text, questions, labels, and tool
  descriptions.
- Provenance: deterministic generator, seed `20261003`, split recorded in each
  record's metadata.
- Data source: synthetic records generated by this repository; public datasets
  are not copied into the training rows.

## Active training configuration

- From-scratch random initialization.
- 20 training epochs.
- Expected optimizer steps: approximately 15,640.
- Decisions processed across epochs: approximately 15,997,640.
- Batch size: 1,024.
- Precision: bfloat16 autocast.
- Learning rate: `0.0002`.
- Choice loss weight: `8.0`.
- Score loss weight: `1.0`.
- Noul loss weight: `1.0`.
- Hardware: one NVIDIA RTX PRO 6000 Blackwell Server Edition.
- Observed VRAM allocation: approximately 85GB of 98GB during training.

## Automatic validation

After the final checkpoint is written, the pipeline automatically runs:

1. Python compilation and checkpoint-load validation.
2. Held-out test evaluation with accuracy, NLL, Brier score, and ECE.
3. Latency and throughput measurement.
4. Tool-router smoke test.

Results are written to the server's local benchmark directory and are not
published until explicitly approved.

## Intended use

Neo is intended for bounded software decisions: tool routing, workflow
selection, classification, scoring, escalation, filtering, and human-review
gates. It is not a conversational model and must not make unsupervised
medical, legal, financial, safety-critical, or irreversible decisions.
